## Checked and found sound
- PTU T3, malformed input (`probes/t3mem.py malformed`). Each of these gives a clean `AdapterError` naming the cause:
  - 1000 maximal HydraHarp v2 overflow records: read correctly, int64 range respected.
  - 9000 overflows at a 1 s sync period: "exceed the int64 ps range". The exact and rounded ps paths both check int64 overflow with Python ints or float margins.
  - PicoHarp T3 record on input 0.
  - dtime beyond the period that breaks time order.
  - Body shorter than the header's record count.
  - Header blob claiming 2^62 bytes.
  - `TTResult_NumberOfRecords` must equal the body size, so record counts cannot drive allocation beyond the file size. Header entries are capped at 100,000.
- No dependency changes since v0.1.1: no diff in pyproject.toml, Cargo.toml or Cargo.lock in any of the three packages. The new code imports only numpy, scipy and pyyaml, which were already declared. YAML is read with a SafeLoader subclass.
- The pinned action SHAs match their stated tags upstream: checkout v7.0.1, setup-python v7.1.0, upload-artifact v7.0.2 and download-artifact v8.0.2, each resolving to the pinned commit via the GitHub API.
- The CI gates job passes `needs.*.result` through `env`, so there is no expression injection. All `${{ matrix.* }}` values in `run:` are static workflow literals. The workflows use `permissions: contents: read` and trigger on `pull_request`, not `pull_request_target`. Shard artifacts flow only within one run, from jobs that run the same code. Each shard writes its own file name, so `merge-multiple` cannot overwrite one shard with another. An unmatched `shards/*.json` glob fails closed. The merge refuses gaps, overlaps and mixed seeds or totals.
- Artifact loading (`--calibrations`, `calibrate deadtime --dark`):
  - The file name must be the content hash, the bytes must be canonical JCS, duplicate keys are refused, the manifest is capped at 16 MB, and `allow_pickle=False` is set.
  - The posterior hash and shape are checked after load (see #2 for the ordering problem).
  - A symlinked `<id>.json` cannot change content: the posterior is resolved next to the link and hash-checked.
  - `previous-artifact` inputs are cited by ID and never resolved to paths, so there is no traversal.
  - Duplicate artifacts are de-duplicated by ID, and two different artifacts of one kind and channel are refused.
- New CLI options:
  - `--rates`: NaN, non-positive and infinite values are refused (`not r > 0` plus `_checks.finite` in `poisson_times`).
  - `--allow-condition-mismatch`: requires a non-blank reason, which is recorded in the artifact notes.
  - `--accept-misfit`: writes the artifact marked misfit, and the status is re-verified on read.
- setup.yaml `dead_time_p_ps` is validated in the schema (integer >= 0) and in `DetectorParams` (an integer no larger than `dead_time_ps`).
